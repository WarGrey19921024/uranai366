# 投入手順書 — 2027年版 誕生日占い 366ページ

> このリポジトリはサイト（WordPress）に触っていません。以下は **翔太さん（またはローカルのセッション）がサイトで行う作業**の手順です。
> 作業前に必ずバックアップ（データベースと `wp-content/uploads`）を取ってください。

## 0. 用意するファイル（すべて `work/out/` の中）

| ファイル | 中身 |
|---|---|
| `wp_all_import.csv` | 366ページ分（タイトル・スラッグ・親ページ・本文・メタディスクリプション）。状態はすべて「下書き」 |
| `assets/`（`fh-b27.css`・`fh-b27.js`・`fh-b27-setsuiri.js`・`fh-b27-kyureki.js`） | 全ページ共通のCSS・JS |
| `redirects_301.csv` | 301の対応表（732件：`/2026-MMDD/` と `/2025-MMDD/` → `/birthday/MMDD/`） |
| `redirects_redirection_plugin.csv` | Redirection プラグインの「インポート」にそのまま読ませる形 |
| `redirects_htaccess.txt` | `.htaccess` で設定する場合の1行 |
| `affiliate_placeholders.csv` | アフィリエイトの仮リンクと置換表（実リンクを記入する列あり） |
| `sample/` | 確認用のサンプルページ（ブラウザでそのまま開ける） |

作り直すとき：`python work/scripts/build_html.py --all` → `python work/scripts/check_pages.py` → `python work/scripts/build_import.py`

## 1. 事前準備（1回だけ）

1. **親ページ `birthday` を作る**（固定ページ、スラッグ `birthday`、タイトル例「誕生日占い 366日」）。公開でよい（中身は一覧ページ）。
2. **共通CSS・JSを置く**：`work/out/assets/` の4ファイルを、サーバーの `wp-content/uploads/fh-b27/` にアップロード（FTP またはファイルマネージャー）。
   - ブラウザで `https://www.uranai.epoch-compass.com/wp-content/uploads/fh-b27/fh-b27.css` が開けることを確認。
3. **アフィリエイトの実リンク**（**仮リンクのまま公開しない**）：仮リンクは全ページで約5,100か所・商品名で約3,700種類あるので、1件ずつ埋めるのではなく、次のどちらかで一括で置き換える。
   - **A. 店ごとの検索リンクのひな形（おすすめ）**：`affiliate_templates.example.json` を `affiliate_templates.json` という名前で写し、楽天のアフィリエイトID・Amazonのタグ・電話占いの広告リンクを書き込む。`{q}` の所に商品名が自動で入る（ラッキーアイテム・プレゼントは楽天やAmazonの検索結果ページへ飛ぶ形）。
   - **B. 個別に決めたい商品だけ**：`affiliate_placeholders.csv` の「実リンク（ここに記入）」列に書く（Aより優先）。
   - そのあと `python work/scripts/apply_affiliate.py` → `python work/scripts/build_import.py` で本文と投入用CSVを作り直す（Claude Code に頼んでもよい）。残りが0か所になったことを確認。

## 2. テスト投入（3ページ）

1. `wp_all_import.csv` から **0101・0229・0120 の3行だけ**を残したCSVを作る（Excel ではなく、文字コードを壊さないエディタで。または Claude Code に「3行版を作って」と頼む）。
2. WP All Import →「新規インポート」→ ファイルをアップロード →「新しいアイテム」→ **固定ページ**。
3. 項目の割り当て：
   | WP All Import の欄 | CSVの列 |
   |---|---|
   | タイトル | `post_title` |
   | 本文 | `post_content`（「テキスト」ではなく**そのままのHTML**として。エディタのビジュアル変換をしない設定） |
   | スラッグ | `post_name` |
   | 親ページ | `post_parent_slug`（「スラッグで親を指定」→ `birthday`） |
   | 状態 | `post_status`（draft＝下書き） |
   | 並び順 | `menu_order` |
   | メタディスクリプション | `meta_description` → 使っているSEOの入れ物に割り当て（Diver の「メタディスクリプション」欄、またはSEOプラグインのカスタムフィールド名） |
4. 「固有キー」は `post_name`（スラッグ）にする（あとで作り直したCSVを入れたときに、同じページを上書きできるように）。
5. 投入後、下書きの3ページをプレビューで確認：
   - [ ] スマホ表示が崩れない（横にはみ出さない）
   - [ ] 月別グラフが表示され、生まれ年を選ぶと線が2本増える
   - [ ] 誕生日カードの「画像で保存」が動く
   - [ ] **目次が二重にならない**（Diver の自動目次とページ内の目次。二重なら、このページだけ Diver の目次を「表示しない」に）
   - [ ] **シェアボタン**がテーマ側で出るか
   - [ ] 生まれ年パネル・バイオリズムカレンダーが動く
   - [ ] メタディスクリプションが入っている
   - [ ] 2/29 のページで生まれ年がうるう年だけ選べる。1/20 のページに星座の境目の注記がある

## 3. 全件投入（366ページ）

1. テストで問題が無ければ、同じ設定（WP All Import の「テンプレートを保存」で保存しておく）で `wp_all_import.csv` 全体を投入（下書きのまま）。
2. 下書きの一覧で 366件あることを確認（親ページ `birthday` の子になっているか）。
3. 数ページをプレビューで確認したら、**一括で「公開」**にする（固定ページ一覧 → 一括操作 → 編集 → 状態：公開）。

## 4. 301リダイレクト（旧URL → 新URL）

**公開した直後**に設定する（公開前に設定すると、転送先が見つからない時間ができる）。どちらか1つの方法で：

- **A. Redirection プラグイン（推奨）**：ツール → Redirection → インポート/エクスポート → `redirects_redirection_plugin.csv` をインポート。732件入ることを確認。
- **B. `.htaccess`**：`redirects_htaccess.txt` の1行を、WordPress のルール（`# BEGIN WordPress`）の**上**に追加。

確認：
- [ ] `https://www.uranai.epoch-compass.com/2026-0101/` を開くと `/birthday/0101/` に1回で飛ぶ（ステータス301）
- [ ] `/2025-0101/` も `/birthday/0101/` に**直接**飛ぶ（`/2026-0101/` を経由しない＝転送の連鎖なし）
- [ ] 旧ページ（2026年版・2025年版の投稿）は、**301が効いていることを確かめてから**非公開（下書き）にする。削除はしない（戻せるように）
- [ ] Search Console で `/birthday/` のサイトマップを送信し、旧URLの「ページの移動」を確認

## 5. 元に戻す方法

| 何を戻すか | 方法 |
|---|---|
| 新ページ366件 | 固定ページ一覧で親 `birthday` の子を一括で「下書き」に戻す（削除しない）。WP All Import の「このインポートで作った投稿を削除」は最終手段 |
| 301 | Redirection：グループごと無効化／`.htaccess`：追加した1行を消す |
| 旧ページ | 下書きにしたものを「公開」に戻す |
| 共通CSS・JS | `wp-content/uploads/fh-b27/` を消す（ページの見た目だけが崩れる。中身は残る） |
