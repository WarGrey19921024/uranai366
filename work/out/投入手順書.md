## 手順3　WAF を一時的にオフ
- [ ] ConoHa WING のコントロールパネル →「サイト管理」→「サイトセキュリティ」→「WAF」を**オフ**にする（大きなHTMLの一括投入がWAFに止められることがあるため）。

## 手順4　テスト投入（3ページ）
- [ ] **管理者アカウント**でログイン（`<script>` を含む本文は管理者でないと保存できない）。
- [ ] WP All Import →「新規インポート」→ `wp_all_import_test3.csv` をアップロード →「新しいアイテム」→ **固定ページ**。
- [ ] 項目の割り当て：

  | WP All Import の欄 | CSVの列 |
  |---|---|
  | タイトル | `post_title` |
  | 本文 | `post_content`（**そのまま**入れる。本文は先頭に `[no_toc]`、その後ろを「カスタムHTML」ブロックで包んであるので、WordPress が段落タグを足して崩すことはない） |
  | スラッグ | `post_name`（`01-01` の形） |
  | 親ページ | `post_parent_slug`（スラッグで指定 → `366uranai`） |
  | 状態 | `post_status`（draft＝下書き） |
  | 並び順 | `menu_order` |
  | カスタムフィールド | 名前 `diver_single_metadescription` ← 列 `diver_single_metadescription`（Diver のメタディスクリプション欄） |
- [ ] 「固有キー」は `post_name`（あとで作り直したCSVを入れるとき、同じページを上書きできるように）。
- [ ] 設定を「テンプレートとして保存」（手順6で使い回す）。
- [ ] 実行して、下書きが3件できたことを確認。

## 手順5　テストの3ページを確認（下書きのプレビュー）

- [ ] 月別グラフが出て、生まれ年を選ぶと線が2本増える／生まれ年パネル・バイオリズムカレンダーが動く

## 手順9　301リダイレクト
公開した**あと**に設定する（公開前だと転送先が無い時間ができる）。どちらか1つの方法で：
- **A. Redirection プラグイン（推奨）**：ツール → Redirection → インポート/エクスポート → `redirects_redirection_plugin.csv` をインポート。734件入ったことを確認。
- **B. `.htaccess`**：`redirects_htaccess.txt` の行を、`# BEGIN WordPress` の**上**に追加。

確認：
- [ ] `/2026-0101/` → `/366uranai/01-01/` に**1回で**飛ぶ（301）。`/2025-0101/` も**直接** `/366uranai/01-01/` へ（`/2026-0101/` を経由しない）
- [ ] `/366uranai/2026y/`・`/366uranai/2025y/` → `/366uranai/` に飛ぶ

## 手順9-2　旧投稿を下書きにする
- [ ] 301が効いていることを確かめてから、2026年版・2025年版の誕生日の投稿（366件ずつ）と、旧ハブ `/366uranai/2026y/`・`/366uranai/2025y/` を**下書き**にする（削除しない＝戻せるように）。
- 子テーマの `jy_append_day_index` は公開中の投稿だけを一覧にするので、下書きにした時点で自動で表示されなくなる（子テーマの変更は不要）。

## 元に戻す方法

| 何を戻すか | 方法 |
|---|---|
| 新しい366ページ | 固定ページ一覧で親 `366uranai` の子を一括で「下書き」に戻す（削除しない） |
| 一覧ページ（ID 2743） | 手順8で保存しておいた元の本文に戻す（または固定ページのリビジョンから復元） |
| まるごと診断 | 下書きに戻す |
| 301 | Redirection：インポートしたリダイレクトを無効化／`.htaccess`：追加した行を消す |
| 旧投稿 | 下書きにしたものを「公開」に戻す |
| 共通CSS・JS | `wp-content/uploads/fh-b27/` を消す（新しいページの見た目だけが崩れる） |
| すべて | 手順1のバックアップから復元 |
